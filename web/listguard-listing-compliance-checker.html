不是关键词包含，是三级归一化匹配

卖家会为了躲扫描故意改写文案，平台也会。规则引擎按三个层次依次匹配，两侧共用同一套归一化，避免「规则写得对但匹配不上」。

LEVEL 1 · FOLD

全角折叠与空白归一

全角 ASCII 转半角、统一小写、移除中日韩字符之间的空白、连续空白折叠为单个空格。规则词与被匹配文本走同一条归一化路径。

ＦＲＥＥ　ＳＨＩＰＰＩＮＧ→命中
LEVEL 2 · CONDENSE

混淆分隔符压缩

折叠后再剥掉全部非字母数字字符，专门对付用连字符、点号、空格拆开敏感词的写法。中文按 Unicode 字母类保留，所以「全 场 最 低 价」同样压得住。

f-r-e-e shipping→命中
LEVEL 3 · REGEX

带词边界的正则

规则包里用 re: 前缀写正则，配合 \b 词边界精确命中独立单词。这决定了工具敢不敢用：误报会让卖家不再信任报告。

secure / sculpture≠cure
这个网页版和命令行版是同一套引擎
页面里的 JavaScript 引擎是从 Java 实现逐条移植的，并用差分测试校验：13 组用例、52 项断言，命中项、分级、字段、建议文本与退出码语义全部一致。规则包同样是同一份 YAML 的数据副本，不存在「网页版偷偷放宽了规则」。

把合规闸门接到你现有的流程里

在线检测台解决「试一下」；真正的价值是让它成为一条不会被人手动跳过的闸门。三种接入方式，按你的角色选。

CI 流水线闸门

退出码就是闸门：0 合规通过、1 命中阈值、2 用法错误。解析失败也算 1——无法解析就无法证明合规（fail-closed）。

- name: Listing compliance gate run: java -jar listguard.jar check listings/ \ --platform amazon --fail-on yellow 查看 GitHub Action 用法 →

SARIF 上传到代码扫描

--format sarif 输出兼容 SARIF 2.1.0，可作为 GitHub Code Scanning 工件直传，命中项以 error / warning 出现在 PR 检查里，评审时就能看到。

java -jar listguard.jar check listings/ \ --platform amazon --format sarif \ > results.sarif SARIF 输出格式说明 →

代运营 / 自有词库

规则包是纯 YAML。--rules-dir 把你的自定义词库追加到内置包之上，适合代运营公司沉淀自家黑话、类目专属红线，词库更新走 code review。

java -jar listguard.jar check listings/ \ --platform temu \ --rules-dir ./our-blacklist/ 自定义规则包格式 →
